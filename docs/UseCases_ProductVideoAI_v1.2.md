# Домен A. Аккаунт и каталог

## UC-01 — Регистрация и автосоздание профиля

Акторы: Посетитель · Приоритет: MVP · Связи: FR-101, FR-106 · US-101 · ТЗ §3.1 (`handle_new_user`)

**Предусловия:** посетитель не зарегистрирован.
**Триггер:** заполнение формы регистрации.

**Основной поток:**

1. Посетитель вводит email и пароль.
2. Система создаёт запись в `auth.users`.
3. Триггер `on_auth_user_created` вызывает `handle_new_user()` и создаёт профиль: `role='user'`, `credits_balance=0`, `region='ru'`, `language='ru'`, `full_name` из метаданных.
4. Система авторизует пользователя и открывает кабинет.

**Исключения:**

* **E1. Email уже занят** — сообщение об ошибке, регистрация не создаётся.

**Постусловия:** существует связка `auth.users` + `profiles`; ручных шагов «завершить регистрацию» нет.

## UC-02 — Вход и работа с сессией

Акторы: Пользователь · Приоритет: MVP · Связи: FR-102, FR-103 · US-102, US-105 · ТЗ §2.1

**Предусловия:** пользователь зарегистрирован.
**Триггер:** ввод учётных данных.

**Основной поток:**

1. Пользователь входит через Supabase Auth.
2. Система выдаёт сессию; становятся доступны его товары, референсы и проекты (только свои — RLS).
3. Черновики проектов в `draft` видны после повторного входа.
4. Пользователь завершает работу выходом; сессия инвалидируется.

**Исключения:**

* **E1. Неверные учётные данные** — 401, вход не выполняется.
* **E2. Запрос с истёкшей сессией** — 401, редирект на вход.

**Постусловия:** после выхода прежняя сессия недействительна.

## UC-03 — Создание карточки товара

Акторы: Пользователь · Приоритет: MVP · Связи: FR-201, FR-204, FR-205, FR-206 · US-201, US-204 · ТЗ §4.2 (`manual-input`), §6.8

**Предусловия:** пользователь авторизован.
**Триггер:** намерение добавить товар.

**Основной поток:**

1. Пользователь заполняет карточку: название (3–200 символов, обязательно), описание (до 4000), цена, категория, ссылка.
2. Система выполняет контент-модерацию описания (ТЗ §6.8).
3. Система сохраняет карточку и возвращает `product_id`.

**Альтернативы:**

* **A1. Редактирование существующей карточки** (из шага 1): изменения применяются к последующим проектам.
* **A2. Удаление карточки:** при наличии активных проектов (`draft`…`assembling`) система отказывает с `ACTIVE_PROJECT_EXISTS`; при отсутствии — подтверждение и каскадное удаление проектов.

**Исключения:**

* **E1. Валидация не пройдена** — `400 VALIDATION_ERROR`.
* **E2. Запрещённый контент в описании** — `CONTENT_POLICY_VIOLATION`, карточка не создаётся.
* **E3. Превышен лимит операций** — `429`.

**Постусловия:** карточка доступна для использования в проектах.

## UC-04 — Загрузка фото товара

Акторы: Пользователь · Приоритет: MVP · Связи: FR-202 · US-202 · ТЗ §4.2 (`upload-presigned`), §3.4

**Предусловия:** карточка товара существует или создаётся.
**Триггер:** выбор файла фото.

**Основной поток:**

1. Фронтенд запрашивает `upload-presigned` (TTL ссылки 900 с).
2. Фронтенд кладёт файл `PUT`-ом напрямую в Storage.
3. Система регистрирует файл в `storage_assets` с `purpose='product_image'`.
4. Фото проходит модерацию (ТЗ §6.8).

**Исключения:**

* **E1. Истёк TTL presigned-ссылки** — новый запрос ссылки.
* **E2. Запрещённый контент на фото** — `CONTENT_POLICY_VIOLATION`.

**Постусловия:** фото связано с карточкой и защищено реестром файлов.

# Домен B. Видео-референс и промпт

## UC-05 — Загрузка видео-донора

Акторы: Пользователь · Приоритет: MVP · Связи: FR-301…FR-305, FR-307 · US-301…US-303 · ТЗ §5.8, §5.8.1, §3.4

**Предусловия:** пользователь авторизован; выбран режим работы с референсом.
**Триггер:** выбор видеофайла.

**Основной поток:**

1. Фронтенд проверяет файл: длительность ≤ 60 с, контейнер, наличие видео-потока.
2. Фронтенд сжимает видео на клиенте: MP4, H.264 + AAC, 480p, ориентация 9:16, FPS ≤ 30, видео ≤ 2500 kbps, аудио 128 kbps.
3. Фронтенд проверяет результат: размер ≤ 150 МБ, длительность ≤ 60 с.
4. Файл загружается через `upload-presigned`; регистрируется в `storage_assets`.
5. Система независимо перепроверяет файл через `ffprobe`.

**Альтернативы:**

* **A1. Браузер не поддерживает сжатие** (из шага 2): показывается сообщение о необходимости меньшего файла; загрузка оригинала запрещена.

**Исключения:**

* **E1. Длительность > 60 с или размер > 150 МБ** — кнопка блокируется: «⚠️ Видео-референс не должен превышать 60 секунд или 150 МБ.»
* **E2. Файл не прошёл серверную проверку `ffprobe`** — отказ до каких-либо списаний.

**Постусловия:** донор принят и защищён от удаления на время активных работ; после завершения проекта подлежит удалению (эфемерность).

## UC-06 — Семантический разбор донора

Акторы: Пользователь · Приоритет: MVP · Связи: FR-308 · US-304, US-305 · ТЗ §4.2 (`analyze-reference`)

**Предусловия:** донор загружен.
**Триггер:** запрос разбора.

**Основной поток:**

1. Пользователь запрашивает разбор референса.
2. Система проверяет доступ (только свой референс) и лимит 10/час.
3. AI-модель выполняет разбор; сохраняются `structure`, `detected_hooks`, `detected_cta`, `tempo`.
4. Результат отображается пользователю.

**Альтернативы:**

* **A1. Повторный разбор того же референса** — возвращается сохранённый результат без повторной оплаты.

**Исключения:**

* **E1. Референс чужой/не найден** — 403/404.
* **E2. Лимит исчерпан** — `429`.
* **E3. Ошибка AI-провайдера** — `502 AI_PROVIDER_ERROR`, не более 2 повторов.

**Постусловия:** разбор сохранён и доступен повторно.

## UC-07 — Генерация промпта из видео

Акторы: Плательщик · Приоритет: MVP · Связи: FR-401…FR-404 · US-306, US-307 · ТЗ §4.2, §7.2, §6.8

**Предусловия:** донор загружен; баланс ≥ 1 кредита.
**Триггер:** запрос генерации промпта.

**Основной поток:**

1. Пользователь запрашивает промпт из референса.
2. Система выполняет модерацию донора (ТЗ §6.8) — до списания кредитов.
3. Система списывает 1 кредит через `charge_credits`.
4. AI-модель генерирует промпт; результат содержит `[PRODUCT_HOLDER]`.
5. Промпт проходит модерацию и сохраняется.

**Альтернативы:**

* **A1. Донор не прошёл модерацию** (из шага 2): кредиты не списываются; пользователь получает отказ `CONTENT_POLICY_VIOLATION` с нейтральным сообщением.
* **A2. Готовый промпт не прошёл модерацию** (из шага 5): списанный кредит возвращается автоматически (ТЗ §6.8).

**Исключения:**

* **E1. Недостаточно кредитов** — `402 INSUFFICIENT_CREDITS`.
* **E2. Ошибка генерации после исчерпания повторов** — автовозврат списанного 1 кредита; запись `refund`.

**Постусловия:** промпт сохранён и готов к использованию в Ветке А.

# Домен C. Кредиты, платежи, подписки

## UC-08 — Пополнение кредитов (разовый платёж)

Акторы: Плательщик · Приоритет: MVP · Связи: FR-801, FR-805, FR-811 · US-403 · ТЗ §4.2, §7.3, §7.7

**Предусловие:** пользователь авторизован.
**Триггер:** намерение пополнить баланс.

**Основной поток:**

1. Пользователь выбирает пакет; цены соответствуют его региону (`ru/us/eu/la`).
2. Система создаёт платёж через `create-payment`: сумма, валюта и кредиты определяются сервером из пакета; строка `payments` создаётся в `pending` только сервером.
3. Пользователь оплачивает через шлюз (prodamus / payselection / lavatop / cryptocloud).
4. Обработка результата — в UC-09.

**Исключения:**

* **E1. Шлюз недоступен** — пользователю предлагается другой доступный шлюз.

**Постусловия:** платёж создан и ожидает подтверждения шлюза.

## UC-09 — Обработка платёжного вебхука

Акторы: Платёжный шлюз · Приоритет: MVP · Связи: FR-806…FR-809 · NFR-403, NFR-505 · US-404…US-408 · ТЗ §7.7, §9.3

**Предусловие:** платёж создан (UC-08).
**Триггер:** вебхук `webhook-payment-:gateway`.

**Основной поток:**

1. Система проверяет подпись шлюза.
2. Система проверяет `event_id` на уникальность.
3. Система сверяет сумму и валюту с созданным платежом.
4. Сохраняются `raw_payload`, `signature_verified=true`, `processed_at`.
5. При `succeeded` одной транзакцией: `payments` + `profiles` + `credit_transactions` — кредиты начислены.
6. Ответ шлюзу `200`.

**Альтернативы:**

* **A1. Повторная доставка вебхука** (из шага 2): ответ 200, баланс не меняется (идемпотентность).
* **A2. Статус `failed`**: платёж отклонён, кредиты не начисляются, повторная оплата разрешена новым платежом.
* **A3. Возврат `refunded` (Фаза 1)**: начисленные кредиты списываются, фиксируется `refund_reason`.

**Исключения:**

* **E1. Невалидная подпись** — `401`, событие не сохраняется.
* **E2. Расхождение суммы/валюты** — `payments.status='failed'`, алерт в мониторинг.
* **E3. Неподписанный запрос** — `401`.

**Постусловия:** баланс изменён ровно один раз на подтверждённую сумму.

## UC-10 — Оформление и жизненный цикл подписки

Акторы: Плательщик, Платёжный шлюз · Приоритет: Ф1 · Связи: FR-812, FR-901…FR-906 · US-501…US-506 · ТЗ §7.3, §7.8

**Предусловие:** пользователь авторизован.
**Триггер:** выбор тарифного плана.

**Основной поток:**

1. Пользователь оформляет подписку через `create-subscription` (планы starter/growth/basic/pro; шлюзы: prodamus, payselection, lavatop, cryptocloud).
2. Подписка создаётся в статусе `trialing` либо `active`.
3. Система начисляет `credits_allowance` периода.
4. События шлюза фиксируются в `subscription_events` (`event_id`, подпись, `status_from`, `status_to`).

**Альтернативы:**

* **A1. Продление периода**: идемпотентное начисление пакета по `event_id`.
* **A2. `past_due`**: начисление следующего периода приостанавливается до погашения.
* **A3. Отмена пользователем**: `active → canceled`; начисленные кредиты не сгорают.
* **A4. Истечение срока**: `expired`; продления нет.

**Исключения:**

* **E1. Событие без подписи или дубль** — отклоняется/игнорируется идемпотентно.
* **E2. Попытка смены статуса без события шлюза** — запрещена.

**Постусловия:** статус подписки всегда соответствует последнему обработанному событию.

# Домен D. Генерация видео

## UC-11 — Классическая генерация видео (Ветка А)

Акторы: Плательщик · Приоритет: MVP · Связи: FR-501…FR-515, FR-701…FR-706, FR-1507 · NFR-101, NFR-901 · US-601…US-613 · ТЗ §6.5

**Предусловия:** карточка товара создана; баланс покрывает стоимость; активных проектов < 2.
**Триггер:** запуск генерации.

**Основной поток:**

1. Пользователь выбирает параметры: длительность 30/60 с, тариф standard/premium, язык, `ugc_type`, `outro_mode` (fade/loop), `audio_mode`.
2. Система отображает точную стоимость (стандарт 35 / премиум 80 за 30 с; ×2 за 60 с; +2 за AI-озвучку) и `eta_minutes`.
3. Пользователь подтверждает; `charge_credits` списывает стоимость; проект → `queued`.
4. Сценарий рассчитывается; статус `script_ready`; пользователь при необходимости корректирует (`user_adjustments`).
5. Система выполняет модерацию сценария (ТЗ §6.8).
6. Генерация озвучки ElevenLabs (голос из `tts_voices` по языку проекта).
7. Базовая генерация видео по схеме ТЗ §6.5: Premium 30 с — один One-take; Premium 60 с — One-take 30 с + один Extend до 60 с; Standard 30 с — база 15 с + Extend 15 с; Standard 60 с — база 15 с + цепочка Extend до 60 с.
8. Финальный монолитный файл передаётся в апскейл до 1080p без FFmpeg-сшивки.
9. Аудио-микс (речь 100%, музыка 15%, SFX 35%; при необходимости дакинг).
10. Проект → `done`; пользователь получает уведомление (UC-13) и результат (UC-14).

**Альтернативы:**

* **A1. Режим `outro_mode='loop'`** (из шага 1): сценарий и визуальный суффикс строятся по промптам Infinite Loop (ТЗ §14.1–14.2).
* **A2. `audio_mode='original_donor'` с референсом**: озвучка не генерируется, кредиты за TTS не списываются.
* **A3. Глобальный лимит 20 генераций достигнут** (из шага 3): проект принимается в `queued` без немедленного старта.
* **A4. Фоллбэк провайдера** (из шага 7): автоматическое переключение по логике ТЗ §5.2; фоллбэк на модель низшего тарифа — только с подтверждением пользователя.
* **A5. Пользователь отклоняет сценарий** (из шага 4): `projects/:id/cancel` переводит проект в `canceled` с полным автовозвратом; перегенерация сценария — Фаза 1.

**Исключения:**

* **E1. Недостаточно кредитов** — `402/400 INSUFFICIENT_CREDITS`, списание не выполняется.
* **E2. 2 активных проекта у пользователя** — `429 ACTIVE_PROJECT_LIMIT`.
* **E3. Превышен лимит 10 созданий/час** — `429` с `Retry-After`.
* **E4. `audio_mode='original_donor'` без `reference_id` с `reference.mode='inpainting'`** — `400 VALIDATION_ERROR` (семантический референс Ветки А режим не открывает).
* **E5. Сценарий не прошёл модерацию** — `failed`, автовозврат.
* **E6. Ошибка провайдера после исчерпания ретраев** — обработка по UC-15.

**Постусловия:** готовый ролик 1080p 9:16 или `failed` с автовозвратом.

## UC-12 — V2V-генерация видео (Ветка Б, Фаза 2)

Акторы: Плательщик · Приоритет: Ф2 (экспериментально) · Связи: FR-306, FR-601…FR-610, FR-1507 · NFR-306, NFR-1004 · US-701…US-709 · ТЗ §6.6

**Предусловия:** донор загружен (UC-05); баланс покрывает оценочную стоимость.
**Триггер:** запуск V2V-генерации.

**Основной поток:**

1. Пользователь подтверждает права на донор в юридической модалке (`v2v_legal_accepted=true`).
2. Проект создаётся в `draft` с `cost_credits = 0`; пользователю показывается `estimated_cost_credits`.
3. Система копирует донор в `/processing/v2v/{project_id}/donor.mp4`.
4. Render Worker измеряет длительность через `ffprobe`; в payload фиксируются `measured_duration_ms`, `duration_exceeded`.
5. Система выполняет модерацию донора (ТЗ §6.8).
6. Система рассчитывает стоимость по измеренной длительности: ≤ 30 с — «30 с + 15»; 31–60 с — «60 с + 15» (если флаг включён, ТЗ §5.3.2.11).
7. `charge_credits` списывает стоимость; `projects.duration_sec` обновляется измеренным значением; проект → `queued`.
8. GPU-задача `v2v_inpaint` выполняется провайдером; результат по вебхуку либо через polling (UC-17).
9. Аудио донора сливается с результатом (`target_duration_ms = measured_duration_ms`).
10. Проект → `done`.

**Альтернативы:**

* **A1. Достигнут лимит 1–2 одновременных V2V-задач** (из шага 8): задача ожидает в `queued`.

**Исключения:**

* **E1. `duration_exceeded = true` (донор > 60 с)** — `failed` с `DONOR_DURATION_EXCEEDED`; списаний не было, возврат не требуется.
* **E2. Донор 31–60 с при выключенном флаге** — отказ на этапе измерения с сообщением о лимите.
* **E3. Файл не читается `ffprobe`** — `failed` до списаний.
* **E4. Нарушение контент-политики** — `failed` с `CONTENT_POLICY_VIOLATION`, списания нет.
* **E5. Нехватка кредитов при списании** — `failed` с `INSUFFICIENT_CREDITS_ACTUAL`; списания не было.
* **E6. Превышен cost-cap Ветки Б** — остановка обработки, автовозврат списанного.
* **E7. Ошибка провайдера после ретраев** — обработка по UC-15.

**Постусловия:** ролик на основе донора готов, либо проект `failed` без финансовых потерь пользователя.

## UC-15 — Обработка упавшего проекта и автовозврат

Акторы: Система · Приоритет: MVP · Связи: FR-707, FR-1201…FR-1207 · NFR-301…NFR-304, NFR-402 · US-1001…US-1007, US-905 · ТЗ §6.2, §7.5

**Предусловие:** активный проект со списанными кредитами.
**Триггер:** ошибка провайдера, валидации, таймаут.

**Основной поток:**

1. Возникает сбой: ошибка провайдера, `MEDIA_VALIDATION_FAILED`, `PROVIDER_TIMEOUT`, `POLLING_EXHAUSTED`, ошибка TTS.
2. Система повторяет шаг по политике ретраев (≤ 3 попыток для GPU/медиа-задач; ≤ 2 для TTS).
3. После исчерпания попыток проект переводится в `failed` с кодом ошибки.
4. Триггер автовозврата вызывает `refund_project_credits` (только при `cost_credits > 0`; идемпотентно по `refunded`).
5. Пользователь получает `project_failed` с человеческим сообщением и подтверждением возврата.

**Альтернативы:**

* **A1. Сбой до списания кредитов** (Ветка Б в `draft`): проект `failed`, возврат не выполняется — возвращать нечего.
* **A2. Задача не завершилась за 6 часов**: принудительный `failed` с автовозвратом.

**Постусловия:** пользователь не платит за несостоявшуюся генерацию; возврат ровно один.

# Домен F. Системные процессы

## UC-17 — Опрос асинхронных задач провайдеров

Акторы: Планировщик · Приоритет: MVP · Связи: FR-1504, FR-1505 · NFR-303 · US-1201 · ТЗ §4.5

**Предусловие:** существуют `gpu_jobs` с `async_mode='polling'`.
**Триггер:** расписание каждые 60 секунд.

**Основной поток:**

1. `poll-async-jobs` вызывается только с `X-Internal-Token`.
2. Отбирается не более 5 задач: `status IN ('pending','processing') AND next_poll_at <= NOW()`.
3. Для каждой задачи запрашивается статус у провайдера; `poll_attempts += 1`; `next_poll_at = NOW() + интервал` (30 с → 60 с → 120 с).
4. Успешный результат обрабатывается нормализованным контрактом (как вебхук) и двигает пайплайн.

**Исключения:**

* **E1. `poll_attempts >= 20`** — задача `failed` с `POLLING_EXHAUSTED`; проект `failed` с автовозвратом (если списано).
* **E2. Вызов без токена** — отказ; пользовательский доступ запрещён.

**Постусловия:** все задачи без вебхуков гарантированно завершаются (успех или отказ) в ограниченный срок.

## UC-18 — Очистка хранилища с защитой активов
