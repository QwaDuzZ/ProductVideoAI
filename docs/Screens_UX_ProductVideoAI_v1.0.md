# Экраны и UX-архитектура ProductVideoAI

**Версия:** 1.0
**Связанные документы:** ТЗ v4.4.3 · Требования (FR/NFR) v1.1 · User Stories v2.1 · Юзкейсы v1.2 · Дизайн-система v5.0
**Принцип:** каждый юзкейс закрыт конкретным экраном; каждый экран имеет одну главную задачу.
**Стиль:** светлая тёплая тема «Sunrise» (Дизайн-система v5.0): бумажный фон, чернильные кнопки, тёмная «сцена» для видео.

---

## 1. Глобальная структура приложения

### 1.1. Каркас (общий для всех экранов)

- **Левый сайдбар** (240 / 64 свёрнутый): логотип · Главная · Проекты · Товары · Референсы · Тарифы · Настройки · внизу: баланс кредитов + профиль.
- **Верхняя панель страницы:** заголовок экрана · хлебные крошки (где нужно) · контекстные действия · индикатор баланса.
- **Контентная область:** до 1200px, отступ 32.
- **Правая панель статуса** (только на экранах создания/генерации): текущий шаг, стоимость, подсказки.

### 1.2. Навигационная логика

- Главный сценарий — **линейный мастер создания видео**: Товар → Референс (опционально) → Настройки → Сценарий → Генерация → Результат. Пользователь всегда понимает, на каком шаге он находится (степпер сверху).
- Все «боковые» сущности (товары, референсы, тарифы) доступны из сайдбара и из мастера через «выбрать существующее».
- Возврат назад по мастеру сохраняет введённое (ничего не теряется).

## 4. Ключевые пользовательские потоки

### 4.1. Поток «Первое видео» (золотой путь)

```
Регистрация (S03) → Онбординг (S05) → Дашборд (S10)
→ «Создать видео» → Мастер: Товар (S20) → Референс (S21, можно пропустить)
→ Настройки (S22) → Сценарий (S23) → подтверждение
→ Генерация (S24) → Результат (S25) → Скачать
```

**Требования к потоку:**
- от входа до старта генерации — не более 6 экранов;
- на каждом шаге мастер показывает степпер «Шаг N из 6»;
- стоимость видна до подтверждения (на шаге Настройки);
- ни на одном шаге нет «тупика» — всегда есть «Назад» и «Дальше/Пропустить».

### 4.2. Поток «Пополнение»

```
Баланс в сайдбаре → «Пополнить» (или инлайн из S53)
→ Тарифы (S40) → выбор пакета → Оплата (S41) → Статус (S42) → зачислено
```

**Требования:** сумма и валюта показываются из ответа `create-payment` (сервер), пользователь никогда не вводит сумму вручную.

### 4.3. Поток «Отказ от сценария» (Б5)

```
Сценарий (S23) → «Отклонить» → Подтверждение (S52):
«Проект будет отменён, N кредитов вернутся на баланс»
→ проект 'canceled' → возврат → тост «Кредиты возвращены»
→ пользователь на Дашборде (может начать заново)
```

### 4.4. Поток «Ошибка генерации»

```
Прогресс (S24) → сбой → Экран ошибки (S50):
что случилось (человечески) + «Кредиты возвращены» (если списано)
+ действия: «Попробовать снова» / «На дашборд»
```

### 4.5. Поток «Админ: зависший проект»

```
Админ-дашборд (S70) → алерт «проекты в очереди > 6 часов»
→ Проекты (S71) → фильтр «зависшие» → проект
→ «Завершить принудительно» → подтверждение (причина обязательна)
→ проект 'failed' + автовозврат + запись в журнал (S72)
```

## 5. Правила пустых и крайних состояний

| Экран | Пустое состояние |
|---|---|
| Дашборд | «Создайте первое видео» + большая кнопка + подсказка пути |
| Каталог товаров | «Добавьте товар, чтобы начать» + кнопка |
| Библиотека референсов | «Загрузите видео-референс» + кнопка |
| История операций | «Операций пока нет» + ссылка на тарифы |
| Список проектов с фильтром | «Ничего не найдено по фильтру» + «Сбросить фильтры» |

**Принцип:** каждое пустое состояние отвечает на вопрос «что делать дальше» одной кнопкой.
